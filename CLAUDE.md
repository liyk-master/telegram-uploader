## Project Overview

A Cloudflare Pages application for uploading `.cas` files to a Telegram channel. The frontend is static HTML/CSS/JS; the backend uses Cloudflare Pages Functions (Workers) with a D1 SQLite database. Authentication is API-key-based. The first registered user becomes admin automatically; subsequent users need a registration code generated by an admin.

## Commands

```bash
npm run dev        # Start local dev server: wrangler pages dev public
npm run deploy     # Deploy to Cloudflare Pages: wrangler pages deploy public
npm run migrate    # Apply D1 migrations to remote DB: wrangler d1 migrations apply telegram-uploader-db --remote
```

**Local dev** requires a `.dev.vars` file (see `.dev.vars.example`):
```
BOT_TOKEN=your_bot_token_here
CHANNEL_ID=your_channel_id_here
```

## Architecture

```
public/                   # Static frontend (deployed to Cloudflare Pages)
  index.html              # Registration page
  dashboard.html          # Main dashboard (upload, leaderboard, admin, history)
  js/api.js               # Shared API helper: apiRequest(), formatSize()
  js/dashboard.js         # All dashboard logic
  css/style.css           # Complete stylesheet

functions/                # Cloudflare Pages Functions (Workers-based API)
  api/_middleware.js      # Auth guard: verifies Bearer token against D1 users table
  api/register.js         # POST — user registration (first user = admin)
  api/upload.js           # POST — single .cas file upload via Telegram sendDocument
  api/upload/batch.js     # POST — batch upload via Telegram sendMediaGroup (≤10 files)
  api/upload/dir-zip.js   # POST — upload a zip of directory files
  api/upload/check-md5s.js# POST — check which content hashes already exist in DB
  api/upload/bot.js       # Multi-bot round-robin helper (selectBot, markRateLimited, clearRateLimit)
  api/leaderboard.js      # GET  — top 20 users by upload_count
  api/user/stats.js       # GET  — current user's stats + paginated upload history
  api/admin/_middleware.js# Admin-only guard (checks is_admin flag)
  api/admin/reg-codes.js  # GET/POST — list or generate registration codes
  api/admin/reset-key.js  # GET/POST — list all users or reset a user's API key
  api/admin/bot-tokens.js # GET/POST/DELETE — manage bot tokens for round-robin

migrations/               # D1 database migrations (applied sequentially)
```

## Key Design Decisions

### API Key & Registration Code Format
- API keys: `tk_` prefix + UUID with dashes removed
- Registration codes: `rg_` prefix + UUID (dashes removed, first 16 chars)
- The first user to register (when `users` table is empty) automatically gets `is_admin = 1` and does not need a registration code

### .cas File Format
A `.cas` file contains a base64-encoded JSON string. The decoded JSON must include:
- `md5` (also checks `MD5`/`Md5` variants) — used as `content_hash` for deduplication
- `size` — the actual file size (may differ from the .cas wrapper size)
- `sliceMD5` / `sliceMd5` / `slice_md5` — optional, stored in `slice_md5` column

### Deduplication
- Single/batch uploads check `content_hash` against the `uploads` table before inserting
- Directory zip upload computes a combined SHA-256 hash of sorted md5s and checks against that
- The `/api/upload/check-md5s` endpoint is used by the frontend to pre-filter already-uploaded files before zipping

### Telegram Upload Flow
- **Multi-bot round-robin**: each upload request selects the least-recently-used bot from the `bot_tokens` D1 table that is not currently rate-limited
- On 429, the bot is marked rate-limited and the request immediately retries with the next available bot (up to 10 attempts)
- On non-429 errors, also tries the next bot
- Batch upload uses Telegram's `sendMediaGroup` (max 10 files per batch); frontend iterates in batches of 10 with a 3s delay between batches
- Upload caption is composed as: `file_path + '\n\n' + caption` (both optional)

### Environment Variables
Set in `wrangler.toml [vars]` and `.dev.vars`:
- `BOT_TOKEN` — Telegram bot token (legacy single-bot fallback; prefer `bot_tokens` table)
- `CHANNEL_ID` — Target Telegram channel ID
- `DB` — D1 database binding (set in `[[d1_databases]]` in wrangler.toml)

### Database Tables
- `users`: id, name, api_key, is_admin, upload_count, total_size, created_at
- `uploads`: id, user_id, file_name, file_size, caption, file_path, status, content_hash, slice_md5, created_at
- `reg_codes`: id, code, used_by, used_at, created_by, created_at
- `bot_tokens`: id, name, token, upload_count, last_used_at, rate_limited_until, created_at

### Frontend State
- API key stored in `localStorage.api_key`
- Page size preference stored in `localStorage.upload_page_size`
- Upload history is server-side paginated (default 10 per page, configurable: 10/20/50/100)
